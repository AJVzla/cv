AMPscript para empezar: personalizar un email con datos de una Data Extension

Por Anthony Mas y Rubi · 19 de noviembre de 2026 · 3 min de lectura

AMPscript es el lenguaje de Salesforce Marketing Cloud para personalizar emails, SMS y CloudPages con los datos de cada contacto. Se ejecuta en el momento del envío: cada persona recibe una versión del email armada con sus datos.

Esta nota cubre lo que más se usa en el día a día. Los ejemplos suponen que el email se envía a una Data Extension con los campos Nombre y Email.

Bloques y salidas

El código va entre %%[ y ]%%. Para mostrar un valor en el HTML se usa %%=v(@variable)=%%.

%%[
  SET @nombre = AttributeValue("Nombre")
]%%

<p>Hola, %%=v(@nombre)=%%</p>

AttributeValue lee un campo de la Data Extension de envío. Si el campo no existe, devuelve vacío en lugar de cortar el envío con un error. Por eso conviene usarlo en vez de escribir el nombre del campo directo.

Valores por defecto

Siempre hay contactos con datos incompletos. Antes de mostrar un dato, revisá si está vacío:

%%[
  SET @nombre = AttributeValue("Nombre")

  IF Empty(@nombre) THEN
    SET @saludo = "Hola"
  ELSE
    SET @saludo = Concat("Hola, ", ProperCase(@nombre))
  ENDIF
]%%

<p>%%=v(@saludo)=%%</p>

ProperCase pone en mayúscula la primera letra de cada palabra, útil cuando los nombres vienen todos en mayúsculas o minúsculas.

Traer un dato de otra Data Extension

Lookup busca en otra Data Extension y devuelve el valor de un campo de la primera fila que coincide:

%%[
  SET @nivel = Lookup("Clientes_Puntos", "Nivel", "SubscriberKey", _subscriberkey)
]%%

Los parámetros son: la Data Extension, el campo que querés traer, el campo por el que buscás y el valor buscado. _subscriberkey es la clave del contacto que está recibiendo el email. Si no hay coincidencia, devuelve vacío.

Mostrar un bloque según el dato

%%[ IF @nivel == "Oro" THEN ]%%
  <p>Tenés envío gratis en todas tus compras.</p>
%%[ ELSEIF @nivel == "Plata" THEN ]%%
  <p>Tenés 10 % de descuento en tu próxima compra.</p>
%%[ ELSE ]%%
  <p>Sumá puntos con cada compra.</p>
%%[ ENDIF ]%%

Podés abrir y cerrar bloques en el medio del HTML. Es la forma más simple de tener una sola pieza con contenido distinto por segmento.

Listar varias filas

Cuando un contacto tiene varias filas en otra Data Extension (por ejemplo, sus últimas compras), se usa LookupRows con un bucle:

%%[
  SET @compras = LookupRows("Compras", "SubscriberKey", _subscriberkey)
  SET @total = RowCount(@compras)

  IF @total > 0 THEN
]%%
<ul>
%%[
    FOR @i = 1 TO @total DO
      SET @fila = Row(@compras, @i)
      SET @producto = Field(@fila, "Producto")
]%%
  <li>%%=v(@producto)=%%</li>
%%[
    NEXT @i
]%%
</ul>
%%[ ENDIF ]%%

LookupRows devuelve hasta 2000 filas. Si necesitás ordenarlas o limitar cuántas mostrar, mirá LookupOrderedRows.

En CloudPages

En una CloudPage el AMPscript se ejecuta cuando alguien abre la página. Dos funciones que vas a usar seguido en formularios:

  • RequestParameter("email") lee un dato enviado por el formulario o por la URL.
  • UpsertData guarda o actualiza una fila en una Data Extension. En emails se usa UpsertDE, que trabaja en el momento del envío.
%%[
  SET @email = RequestParameter("email")
  SET @nombre = RequestParameter("nombre")

  IF NOT Empty(@email) THEN
    UpsertData("Registros", 1, "Email", @email, "Nombre", @nombre, "Fecha", Now())
  ENDIF
]%%

El 1 indica cuántos pares de campo y valor forman la clave para buscar la fila. Validá siempre los datos del formulario antes de guardarlos.

Errores comunes

  • Comillas tipográficas: si copiás código desde Word o Google Docs, las comillas “curvas” rompen el script. Usá siempre comillas rectas.
  • Nombres de campos: tienen que coincidir exactamente con los de la Data Extension, incluidos los espacios.
  • No probar con datos reales: usá la vista previa con contactos de la Data Extension, incluidos algunos con campos vacíos.
  • Lógica en todos lados: conviene declarar las variables en un bloque al principio y dejar el HTML solo con las salidas. Es más fácil de leer y de mantener.
